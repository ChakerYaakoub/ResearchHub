# Internationalization (i18n)

| Item | Detail |
|------|--------|
| Library | `i18next` + `react-i18next` |
| Locales | [`src/i18n/locales/en.json`](../src/i18n/locales/en.json), [`fr.json`](../src/i18n/locales/fr.json) |
| Config | [`src/i18n/config.ts`](../src/i18n/config.ts) — `rh_lang`, supported `en`/`fr`, detect |
| Bootstrap | [`src/i18n/index.ts`](../src/i18n/index.ts) — init + `setAppLanguage` |
| Persistence | `localStorage` key `rh_lang` |
| Detection | stored lang → browser `fr*` → `en` |

User-visible copy goes through `useTranslation()` / `t('…')` in the locale JSON files. Keep **en** and **fr** keys in sync when adding strings.

Language switcher appears in `PublicLayout` and `DashboardLayout`.

## Key areas (top-level)

| Group | Used for |
|-------|----------|
| `common`, `validation`, `errors`, `toast` | Shared UI |
| `nav`, `seo` | Chrome and document titles |
| `home`, `howItWorks`, `documentation` | Public marketing |
| `dashboard`, `projects`, `proposal`, `experiments`, `publications` | Researcher app |
| `invitations`, `account` | Invitations + profile |
| `login`, `register`, `forgot`, `reset` | Auth modal forms |

API `detail` / error strings may be shown as returned from the backend (not always translated).
